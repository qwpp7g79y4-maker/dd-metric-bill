## [Unreleased]

### Added

- SIGINT exits 130. Stderr is `interrupted by SIGINT`. The report is not left half-written: `--output` keeps the previous file until the new report is complete, and a signal before that writes nothing. Ordinary exit codes stay 0, 1, 2 and 3. No price and no provider were added. The input limit stays 268435456 bytes.
- Each sample, each price file, and standard input may be at most 268435456 bytes (256 MiB). A larger input exits 2 with `file is larger than 268435456 bytes` and is not loaded. The measured 100 MiB input stays under this limit. Exit codes stay 0, 1, 2 and 3. No price and no provider were added.
- `tests/offline.rs`: `webshop_count_is_reported_with_outgoing_connections_blocked` runs `count` on `examples/webshop.dogstatsd` in a network namespace (`unshare --user --map-root-user --net`) whose route table is empty. The report matches `examples/webshop.expected.txt`. No price and no provider were added.
- `--output PATH`, on count and diff, writes the report to a file instead of stdout. An existing file is replaced. A missing parent directory is not created and exits 2, the same code as a failed write to stdout. `completions` ignores the flag and still prints the script on stdout. Exit codes stay 0, 1, 2 and 3. No price and no provider were added.
- `--quiet` and `--verbose`, on count and diff. A pipe or a redirect omits the `hint:` line. `--verbose` prints that line, and on success one `context:` line on stderr. `--quiet` omits the hint even on a terminal. The report on stdout is unchanged. Exit codes stay 0, 1, 2 and 3. `--quiet` together with `--verbose` is exit 3.
- `dd-metric-bill completions <bash|zsh>` prints a shell completion script, generated by `clap_complete` (rust-version stays 1.85). The man page and both READMEs describe it.
- README.md and README.nl.md: section "Aan de slag in 5 minuten" with five offline commands on `examples/`, `tests/fixtures/` and `prices/`. `tests/readme.rs` runs them literally.
- `count` adds an advice line for each metric with unbounded tag keys: the billable count with and without those keys. JSON output gets an `advice` object under `unbounded`.

### Changed

- The README and the quality reports state the measured test count: 301.

## [1.0.0] - 2026-11-08

The previous version is 0.1.2. The changes below, including the breaking ones, are in 1.0.0.

### Added

- `README.md` and `README.nl.md` have Example and Options sections; every option of `--help` is in both. `examples/` has two more fictional samples (`webshop.dogstatsd`, `api-gateway.prom`) with their expected output, compared by `tests/examples.rs`, and the release archive ships `examples/`.
- Manual page `man/dd-metric-bill.1`, and a fictional DogStatsD sample under `examples/` with the command and its exit code.

### Changed

- Errors on stderr for an unreadable sample or price file, a line that does not parse, an invalid price file, a budget overrun, and a count that does not fit are followed by a `hint:` line that says what you can do. The first line, the stdout, and the exit codes are unchanged.
- The README states the test count, the same number as the quality report.
- Breaking: `Sample.name`, `Tag.key`, and `Tag.value` are now `Arc<str>` (the type `parse::Text`) instead of `String`.
- Breaking: `#HOST:a,HOST:b` (two values that are the same `host` key after lowercasing) now exits with 2, like `#host:a,host:b`.
- Counting lowercases tags, so a `Sample` built through the public API with `HOST:a` counts the same as a parsed `host:a`. The tags in the `Sample` are not changed.
- `unique_hosts` and the `host` conflict check lowercase key and value with the same rule, so a hand-built `HOST:A` is the host `a` and `HOST:a` with `host:b` conflicts. Tags that only change as titlecase letters (such as U+01C5) are lowercased too.

### Fixed

- Tags are counted in lowercase, as Datadog stores them: `Env:Prod` and `env:prod` are one series, and `HOST` is the `host` tag. `--allow-tags` keys are lowercased too. Metric names stay case sensitive.
- Counting uses much less memory and time: names, tag keys, and tag values are stored once, and a series is a short list of ids instead of nested trees of strings. A sample of 900,000 unique series (64 MB) went from about 1.3 GB and 24 seconds to about 370 MB and 10 seconds. There is still no streaming mode.

### Build

- A `fuzz/` crate (cargo-fuzz) covers every parser, the price and cost calculation, the allow-list simulation, diff, and render to text and JSON; a cheap nightly build-only CI job keeps it compiling.
- Property tests (proptest) check that parsers never panic on arbitrary bytes, that the cost calculation matches plain arithmetic, and that `count` and `diff` output stays stable and its JSON always parses.
- More edge-case tests: a lone CR, a very long line, NUL bytes, Unicode whitespace and lookalike letters, and numbers such as `1e309` and `-0`.

## [0.1.2] - 2026-10-14

### Fixed

- Prices are read as exact decimals instead of through binary floating point. A price with more than 12 decimals, or out of range, is refused with exit 2.
- `diff` no longer panics when a total does not fit in a signed 64-bit number.
- A Prometheus histogram and a counter whose series names collide are counted once, and the `diff` total matches its per-metric deltas.
- A write error, such as a full disk, is a clean error instead of a panic. `--help` and `--version` do not exit 0 when their output cannot be written.
- Control characters in a price file's currency, source and date, and in metric names, are escaped in text output and on stderr.
- A path that is swapped for a FIFO between the check and the read no longer makes the tool wait; the opened file itself is checked.
- The quick start in the README works from the release archive.

### Performance

- Many repeated sample lines no longer grow memory without bound.
- Lookups per metric use a map, so time grows linearly with the number of unique metric names instead of quadratically.

## [0.1.1] - 2026-10-11

### Changed

- The usage line in error messages names the binary `dd-metric-bill` on every platform (it showed `dd-metric-bill.exe` on Windows).
- A price file that starts with a UTF-8 BOM is now read, as samples already were.

### Added

- Release binaries for `x86_64-unknown-linux-musl` (static, also for Alpine).
- Release archives include `README.nl.md` and the reference in `docs/`.
- System requirements per platform in the README.

### Build

- Releases run the full test suite on the tagged commit first, and each archive is unpacked and run with `--version` before it is published.
- CI also tests on macOS Intel and runs clippy on Rust 1.85.

## [0.1.0] - 2026-10-11

### Added

- `count`: estimate billable Datadog custom metrics in one or more samples (DogStatsD, JSON lines, or Prometheus text).
- `diff`: compare two samples, with new and removed metrics and the change per metric and per tag key.
- `--explain`: show the billing rule and its source for each metric.
- `--json`: JSON output with `schema_version` 1.
- `--budget`: exit 1 when the count (or, for `diff`, the new total) is above N.
- `--plan` and `--hosts`: show the Pro or Enterprise allotment.
- `--allow-tags`: separate ingested custom metrics from indexed ones.
- `--prices`: read a price file and estimate the cost above the allotment.
- `--unbounded-threshold`: mark tag keys with too many values, or with an id-like value.
- `--histogram-aggregates`, `--histogram-percentiles`, and `--percentiles`: the histogram and distribution factors.
- `--untyped-as`: count Prometheus metrics without a type as gauge or count.
